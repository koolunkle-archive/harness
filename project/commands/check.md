# 프로젝트 내 모든 `.html` 파일을 대상으로 아래 항목을 점검하고, 최종적으로 "통과 / 수정필요" 표로 결과를 보고한다

## 점검 절차

1. **파일 수집**: 프로젝트 전체에서 `*.html` 파일을 모두 찾는다 (Glob 사용, `node_modules` 등 불필요한 디렉토리는 제외).
2. **제목 점검**: 각 HTML 파일을 읽어 `<title>` 태그가 존재하는지, 비어있지 않은지 확인한다. 없거나 비어있으면 "수정필요"로 표시한다.
3. **깨진 링크 점검**: 각 파일 내의 `href`, `src` 속성을 모두 찾는다.
   - 내부 링크(상대 경로)는 실제로 해당 파일이 존재하는지 확인한다.
   - 외부 링크(`http://`, `https://`)는 static 사이트 규칙상 실제 요청은 보내지 않고 형식만 육안 확인하거나, 필요 시 WebFetch로 상태코드를 확인한다.
   - 앵커(`#id`) 링크는 대상 페이지에 해당 `id`가 존재하는지 확인한다.
   - 존재하지 않는 파일/앵커를 가리키면 "수정필요"로 표시하고 어떤 링크가 깨졌는지 기록한다.
4. **콘솔 에러 점검**: `claude-in-chrome` 스킬 및 관련 도구(`mcp__claude-in-chrome__*`)를 사용해 각 HTML 파일을 브라우저 탭에서 직접 열고(`file://` 경로), `read_console_messages`로 에러/경고를 확인한다.
   - 브라우저 자동화를 사용할 수 없는 환경이면, 그 사실을 표에 명시하고 대신 `<script>` 블록의 명백한 문법 오류나 정의되지 않은 함수 참조 등을 정적으로 점검한다.
   - 콘솔에 error 레벨 로그가 있으면 "수정필요"로 표시한다.

## 보고 형식

점검이 끝나면 아래와 같은 마크다운 표로 결과를 정리해서 보고한다. 파일별로 한 행씩 작성한다.

| 파일 | 제목 | 깨진 링크 | 콘솔 에러 | 상태 |
| --- | --- | --- | --- | --- |
| index.html | ✅ "홈페이지" | 없음 | 없음 | 통과 |
| about.html | ❌ 제목 없음 | `./intro.html` 없음 | - | 수정필요 |

- "상태" 열은 세 항목이 모두 이상 없을 때만 "통과", 하나라도 문제가 있으면 "수정필요"로 표기한다.
- "수정필요" 항목에는 구체적으로 무엇이 문제인지(누락된 파일명, 빈 제목 등) 간단히 적는다.
- 표 아래에 전체 파일 수, 통과 수, 수정필요 수를 요약 한 줄로 덧붙인다.
- 코드 수정은 사용자가 별도로 요청하기 전까지 하지 않는다 (점검 및 보고만 수행).
