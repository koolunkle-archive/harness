# SEO / GEO 점검 및 수정

대상: 현재 프로젝트의 모든 `*.html` 파일 (먼저 Glob으로 전체 목록을 파악한다. `node_modules`, `dist`, `build` 등 산출물 폴더는 제외).

배포 주소: `$ARGUMENTS`
인자가 없으면 작업을 시작하기 전에 사용자에게 배포 주소를 물어본다(sitemap.xml·robots.txt에 절대 URL이 필요하기 때문). 아직 배포 전이라 주소가 없다고 하면 사용자가 알려주는 placeholder 도메인을 그대로 쓰고, 나중에 실제 주소로 바꾸라고 안내한다.

아래 다섯 항목을 순서대로 처리한다. 한 항목을 끝낼 때마다 무엇을 바꿨는지 한두 문장으로 보고한다.

## 1. Title / Meta Description — 페이지마다 다르게

- 각 HTML의 `<title>`과 `<meta name="description">`을 실제 본문 내용에 맞춰 새로 쓴다. 절대 복사-붙여넣기로 재사용하지 않는다 — 같은 문구가 두 페이지 이상에 나오면 실패로 간주한다.
- title은 55자, description은 120자 내외를 넘기지 않는다(과도하게 길면 검색결과에서 잘린다).
- title 형식은 `핵심 키워드 — 브랜드명`처럼 페이지 고유 키워드를 앞에 둔다.
- description은 그 페이지에서만 답할 수 있는 구체적인 내용(다루는 대상, 얻을 수 있는 결과)을 담는다. "다양한 정보를 제공합니다" 같은 일반론 문장은 쓰지 않는다.
- `<meta name="description">`이 없는 페이지는 새로 추가하고, `<title>`이 비어있거나 사이트명만 있는 페이지도 채운다.

## 2. 구조 점검 — h1 / 시맨틱 랜드마크 / alt

- 페이지마다 `<h1>`이 정확히 1개인지 확인한다. 0개면 페이지 핵심 주제를 담은 h1을 추가하고, 2개 이상이면 진짜 페이지 제목만 h1으로 남기고 나머지는 문맥에 맞게 h2/h3로 내린다.
- h1 → h2 → h3 순서가 건너뛰지 않는지(예: h1 다음 바로 h4) 확인하고 어긋나면 바로잡는다.
- 모든 페이지가 `<header>` / `<main>` / `<footer>` 랜드마크를 갖추고 있는지 확인한다. 없으면 추가하고, 본문 콘텐츠가 `<main>` 밖에 있으면 안으로 옮긴다. `<main>`은 페이지당 1개만 있어야 한다.
- 모든 `<img>` 태그에 그 이미지의 실제 내용을 설명하는 `alt`가 있는지 확인한다. 장식용 이미지는 `alt=""`로 명시한다. 순수 장식 아이콘(SVG 등)은 `aria-hidden="true"`가 있는지 확인하고, 의미를 전달하는 아이콘(버튼 등)은 `aria-label`이 있는지 확인한다.

## 3. sitemap.xml / robots.txt 생성

- 프로젝트 루트에 있는 모든 `*.html`을 대상으로 `sitemap.xml`을 생성한다(이미 있으면 최신 목록으로 갱신). `<loc>`은 `배포 주소 + 경로`의 절대 URL로 쓰고, `index.html`은 루트 경로(`/`)로 정규화한다. 각 `<url>`에 `<lastmod>`(오늘 날짜, YYYY-MM-DD)를 넣는다.
- 프로젝트 루트에 `robots.txt`를 생성한다. 일반 크롤러는 전체 허용하고, 아래처럼 주요 AI 크롤러도 명시적으로 허용한다(차단 목록이 아니라 허용 목록으로 명시해야 "AI 로봇도 허용"이 확실해진다):

```
User-agent: *
Allow: /

User-agent: GPTBot
Allow: /

User-agent: ChatGPT-User
Allow: /

User-agent: Google-Extended
Allow: /

User-agent: ClaudeBot
Allow: /

User-agent: anthropic-ai
Allow: /

User-agent: PerplexityBot
Allow: /

User-agent: CCBot
Allow: /

Sitemap: {배포 주소}/sitemap.xml
```

- 위 크롤러 목록은 예시이며, 프로젝트에 이미 다른 크롤러 정책이 있다면 덮어쓰지 말고 병합한다.

## 4. (GEO) 소제목을 질문형으로 + 첫 문장에서 바로 답하기

생성형 AI 검색(챗봇 답변)이 문단을 그대로 인용하기 쉽게 만드는 작업이다.

- 본문의 소제목(h2/h3 등, 페이지 제목인 h1은 제외)을 훑어보고, 서술형·명사형 소제목을 독자가 실제로 검색할 법한 질문형으로 바꾼다. 예: "구조 우선" → "왜 구조부터 파악해야 할까?"
- 소제목을 바꾼 뒤에는 바로 다음 문단의 첫 문장이 그 질문에 대한 결론만 담긴 직접적인 답이 되도록 고친다. 배경 설명이나 부연은 그 다음 문장부터 이어간다. (나쁜 예: "여러 이유가 있는데..."로 시작 / 좋은 예: 질문의 핵심 답을 담은 한 문장으로 바로 시작)
- 기존 문장의 정보량은 유지하면서 순서와 소제목만 재구성한다. 사실관계를 새로 지어내지 않는다.

## 5. (GEO) 모호한 조언을 구체적 숫자와 근거로

- "여러 번 반복한다", "충분히 쉬어준다", "짧게 자주 본다"처럼 정도를 알 수 없는 표현을 찾아서, 실행 가능한 구체값(횟수, 기간, 분량, 순서)으로 바꾼다.
- 예: "반복해서 암기한다" → "같은 내용을 하루·3일·7일 간격으로 총 3회 반복한다" / "짧게 쉰다" → "25분 집중 후 5분 휴식(뽀모도로)을 반복한다"
- 단, 검증할 수 없는 연구·통계·수치를 지어내서 근거처럼 포장하지 않는다. 존재를 확인할 수 없는 논문·기관·퍼센트 수치는 절대 만들어내지 않는다. 대신 페이지 자체의 방법론에서 나오는 구체값(반복 횟수, 시간 배분, 문항 수 등)을 쓰거나, 근거가 필요한 경우 "왜 그 숫자인지"를 논리적으로 한 문장 덧붙인다(예: 분산 반복은 며칠 간격을 둘 때 망각 직전에 다시 노출되어 기억이 오래간다는 원리를 한 줄로 설명).
- 이미 구체적인 문장은 건드리지 않는다. 모든 문장에 억지로 숫자를 넣지 말고, 정말 모호한 조언만 골라서 고친다.

## 마무리

모든 항목을 처리한 뒤, 어떤 페이지의 title/description이 어떻게 바뀌었는지, h1/구조에서 무엇을 고쳤는지, sitemap/robots를 어느 주소로 생성했는지, 소제목·문장을 몇 군데 고쳤는지를 간단한 목록으로 요약해서 보고한다.
