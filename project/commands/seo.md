# 프로젝트 내 모든 `.html` 파일을 대상으로 아래 항목을 점검·수정한다 (SEO + GEO)

## 작업 절차

1. **파일 수집**: 프로젝트 전체에서 `*.html` 파일을 모두 찾는다 (Glob 사용, `node_modules` 등 불필요한 디렉토리는 제외).

2. **title / meta description 개별 작성**
   - 각 HTML 파일의 `<title>`과 `<meta name="description">`를 페이지 실제 내용에 맞게 각각 다르게 작성한다.
   - 여러 페이지가 동일하거나 유사한 title/description을 쓰고 있으면 페이지 고유 내용(핵심 주제, 다루는 대상/카테고리 등)을 반영해 구분되도록 고친다.
   - title은 너무 길지 않게(권장 60자 내외), description은 페이지 요약이 드러나도록 100~160자 내외로 작성한다.

3. **구조 점검**
   - 페이지당 `<h1>`이 정확히 1개만 존재하는지 확인하고, 여러 개면 하위 제목은 `<h2>` 이하로 낮춘다.
   - `<header>`, `<main>`, `<footer>` 시맨틱 구조가 갖춰져 있는지 확인하고, 빠져있으면 보완한다.
   - 모든 `<img>`의 `alt` 속성이 존재하고 이미지 내용을 설명하는지 점검한다. 없거나 비어있으면 구체적인 대체 텍스트를 채운다. 장식용 이미지는 `alt=""`로 명시한다.

4. **sitemap.xml / robots.txt 생성**
   - 실제 배포 주소를 기준으로 `sitemap.xml`을 생성/갱신한다 (전체 HTML 페이지 포함, `lastmod`/`changefreq`/`priority` 포함).
   - `robots.txt`를 생성/갱신한다. 일반 검색엔진 크롤러뿐 아니라 AI 크롤러(GPTBot, ChatGPT-User, OAI-SearchBot, Google-Extended, ClaudeBot, Claude-User, anthropic-ai, PerplexityBot, Perplexity-User, CCBot, Bytespider 등)도 명시적으로 허용(Allow)한다.
   - `robots.txt` 하단에 `Sitemap:` 라인으로 sitemap.xml 절대경로를 명시한다.
   - 배포 주소를 특정할 수 없으면 기존 `sitemap.xml`/`robots.txt`에 이미 기록된 도메인을 사용하고, 그마저 없으면 작업 전 사용자에게 배포 주소를 확인한다.

5. **(GEO) 소제목을 질문형으로, 첫 문장에서 직접 답하기**
   - 본문의 `<h2>`/`<h3>` 등 소제목 중 서술형인 것을 독자가 검색·질문할 법한 질문형 문장으로 바꾼다 (예: "효과적인 집중 전략" → "집중력을 높이려면 어떻게 해야 할까?").
   - 각 소제목 바로 다음 문단의 첫 문장이 그 질문에 대한 직접적인 답이 되도록 고친다. 배경 설명이나 도입부로 문단을 시작하지 않는다.

6. **(GEO) 모호한 조언을 구체적인 숫자·근거로 교체**
   - "짧게", "자주", "충분히", "효과적으로" 같은 모호한 표현을 구체적인 수치(시간, 횟수, 분량 등)로 바꾼다 (예: "짧게 쉬어라" → "25분 집중 후 5분 휴식하라").
   - 근거 없는 단정은 통계, 연구 결과, 도메인 이론 등 뒷받침할 수 있는 이유와 함께 제시한다. 사실을 지어내지 말고, 근거를 명확히 제시할 수 없는 조언은 "~하는 경향이 있다" 같은 절대적 단정 대신 합리적인 근거를 덧붙이는 방향으로만 다듬는다.

## 규칙

- 이 프로젝트는 서버/API/키 없이 정적 파일(HTML/CSS/JS)만으로 구성된다. 수정 시에도 이 제약을 지킨다.
- 파일이 300줄을 넘게 되면 코드를 작성하기 전에 파일 분리를 먼저 제안한다.
- 실제로 파일을 수정하기 전, 점검 결과를 페이지별로 요약해 보여주고 어떤 항목을 고칠지 파악한 뒤 수정을 진행한다.
- 모든 수정이 끝나면 파일별 변경 요약을 표로 보고한다.
